# skullsploit

Black-and-white, key-invited script hub. Comfy noir.

## Run

```bash
npm install
SEED_DEV_PASSWORD='pick-a-strong-one' npm start
```

Then open http://localhost:3000

The first time the server boots, it creates a single bootstrap developer account using `SEED_DEV_USERNAME` (defaults to whatever `OWNER_USERNAME` is, defaults to `owner`) and `SEED_DEV_PASSWORD`. The server **refuses to start** if `SEED_DEV_PASSWORD` is unset on a fresh install — there is no hardcoded fallback. After the first boot the env var is no longer needed (the password is hashed into `data/devs.json`); rotate it from the CLI any time with `scripts/set-dev-password.js`.

## Roles

| Role          | What they can do                                                         |
| ------------- | ------------------------------------------------------------------------ |
| **owner**     | Everything below + manage devs, mint keys, audit log, morph admin.       |
| **developer** | Publish scripts, run the obfuscator, browse logs.                        |
| **morph**     | A regular user promoted by an owner — can manage the morphs page.        |
| **member**    | Browse games + scripts, like scripts, join games.                        |

Owners are devs with `isOwner: true`. The bootstrap account is always an owner.

## Setup

1. Set `SEED_DEV_PASSWORD` and `SEED_DEV_USERNAME` (optional, defaults to `OWNER_USERNAME`) in your environment.
2. Run `npm start` once to seed the bootstrap dev.
3. Sign in at `/login` as that user.
4. Mint invite keys at `/owner` to onboard members and other devs.

### Rotating a developer password

Use the included script — works from the server CLI without a website login:

```bash
sudo systemctl stop skullsploit
node scripts/set-dev-password.js <username> '<new_password>' [--data /abs/path/devs.json]
sudo systemctl start skullsploit
```

The script searches common locations for `data/devs.json`; pass `--data` if it can't find yours.

### Adding members

Members sign up at `/signup` using a one-use **invite key**. Owners mint invite keys at `/owner`. Each key creates exactly one account, then is marked `consumed`.

## Environment variables

| Variable             | Default                | Purpose                                                  |
| -------------------- | ---------------------- | -------------------------------------------------------- |
| `PORT`               | `3000`                 | HTTP listen port                                         |
| `SESSION_SECRET`     | autogenerated          | Express-session secret (persisted in `data/.session-secret`) |
| `OWNER_USERNAME`     | `owner`                | Username of the bootstrap owner                          |
| `SEED_DEV_USERNAME`  | `OWNER_USERNAME`       | Username used at fresh seed                              |
| `SEED_DEV_PASSWORD`  | *(required on seed)*   | Initial password; server refuses to start if unset on fresh install |
| `HEARTBEAT_SECRET`   | unset (open)           | Optional shared secret for `/api/games/heartbeat`        |
| `PLACE_STALE_DAYS`   | `30`                   | Auto-prune places not heartbeating in N days; `0` disables |
| `SITE_URL`           | derived from request   | Authoritative origin for `/m.lua` loader URL             |
| `NODE_ENV`           | unset                  | Set to `production` for prod cookie behavior             |

## Data files

- `data/devs.json` — developer accounts (edit by CLI script only)
- `data/users.json` — member accounts (created via signup with a key)
- `data/keys.json` — invite keys
- `data/scripts.json` — script hub entries
- `data/morph-custom.json` — morph hub entries (built-ins + custom)
- `data/morph-whitelist.json` — Roblox usernames allowed to use the morph hub
- `data/morph-log.json` — usage log for the morph hub
- `data/audit.json` — append-only audit log
- `data/places.json` — every game that has ever heartbeated
- `data/logs.json` — script execution logs

## Security notes

- Bootstrap password must be set via `SEED_DEV_PASSWORD` — no hardcoded default.
- Login uses constant-time bcrypt comparison (compares against a dummy hash when the username doesn't exist) to prevent timing-based username enumeration.
- Sessions are httpOnly + sameSite + signed; secret persists across restarts in `data/.session-secret`.
- Morph endpoints (`/api/morphs`) are gated by `?u=USERNAME` matching a whitelist entry, plus session bypass for morph-access users.
